# kb-search

用户问的东西如果可能躺在他的书库里，就先查库再回答；不要凭记忆补一个看起来合理的页码。
这个 skill 规定一次检索怎么拆词、怎么分语言查、怎么合并、读到哪一层、最后怎么引用。

工具只有一个入口：`kb_query`。它一次只匹配一个词袋（bag of terms），不做句法理解，
所以整句塞进去基本等于随机抽样。下面所有例子里的 `<尖括号>` 都是占位符，换成用户
问题里的实际词，不要照抄。

## 1. 拆词：3–8 个高信号词

先判断问题里哪几个词是"库里真的会出现"的词，再决定查什么。一次查 3–8 个词：
少于 3 个容易命中整章，多于 8 个等于要求全部同时出现，召回骤降。

| 词位 | 作用 | 占位示例 |
| --- | --- | --- |
| 主体 | 问题围绕的对象 | `<主体>` |
| 属性 | 想知道的那个量或论点 | `<属性中文>` / `<attribute english>` |
| 限定 | 版本、条件、范围 | `<限定>` |
| 标识 | 型号、标准号、编号 | `<编号>`（用户给了才用） |
| 同义 | 一个替换说法 | `<同义词>` |

规则：

- 疑问词不进词袋：怎么、为什么、多少、区别、原理、有哪些，这些词在几乎所有页上都出现。
- 一个词位一个词。同一词位塞五个近义词，等于把召回换成噪声；要变体就用同义位或第二次查询。
- 保留原文里的编号和符号（`<编号>`、`<符号>`），它们是最稀有的词。
- 词太长就砍掉修饰语，只留中心词；中文两字词通常比四字短语更好命中。

三个领域的**提问形状**（只是形状，不是内容；不要假设某个领域才这样问）：

- 电子类：`<器件> 的 <参数> 在 <条件> 下是多少` → 查 `<参数中文> <器件>`、`<parameter english> <device>`。
- 数学类：`<定理> 在什么 <条件> 下成立、<结论> 怎么表述` → 查 `<定理名> <条件词>`、`<theorem english> <condition>`。
- 文学类：`<作者> 在 <作品> 里怎么处理 <主题>` → 查 `<作者> <作品>`、`<author> <theme english>`。

## 2. 中文一轮、英文一轮，不要混排

`kb_query` 的分数是词袋层面的：中英混在一个 query 里，两种语言各自只分到一半权重，
两边都排不到前面。分开发两次调用，再合并。

- 先查用户语言那一轮（中文问题先中文），它决定基线。
- 再查英文一轮：手册、论文、教材的术语、公式名、标准名往往是英文；中文书里的英文术语也按英文查。
- 最多 2–4 轮。每轮保持 3–8 个词，不要因为第一轮没命中就把整段问题丢进去。
- 第一轮的前几条如果已经明显跑偏（见第 5 节），换词位重拆，而不是在同一组词上加词。

调用形状：

```json
{ "query": "<属性中文> <主体中文>", "topK": 8 }
```

```json
{ "query": "<attribute english> <subject english>", "topK": 8 }
```

如果工具支持一次给多个改写（`queries`），把同一轮的 2–3 个写法放进去；不支持就老实
分多次调用。不要假设参数存在，先看当前工具签名。

## 3. 按页合并

两轮结果按 `path + page` 合并，同一页只留分数最高的那条片段：

| path | page | section | score | 用途 |
| --- | --- | --- | --- | --- |
| `<path>` | `<page>` | `<section>` | 最高分 | 候选，待读 |
| `<path>` | `<page>` | `<section>` | 次高 | 同一页，合并 |

- 相邻页（±1）通常属于同一节，合并成一个窗口看待，不要当成两条独立证据。
- 同一个文件命中 5 页以上，说明这个词组在这个文件里是主题词：可以只留前 2–3 页。
- 不同文件各命中一两页，先各读一页，比较哪本真的在回答这个问题。

## 4. 只展开最好的 1–2 条

命中片段通常只有一两句，不足以判断。对合并后的前 1–2 条：

- 用 `expand` 展开为整页或整节（当前工具支持 `page` / `section` 就优先用），或读相邻页；
- 读的时候找"定义、条件、取值、例外"这几类句子，它们才是可引用的内容；
- 不要把所有命中都展开：既慢，也会让上下文被无关段落淹没。

## 5. 判读与降级

不是每条命中都能用。按顺序检查：

1. **目录页 / 索引页**：整页是"…… 12"式的行，或标题是目录、Index、Contents。跳过，用更具体的词重查。
2. **近空页**：正文不足一二百字，多半是扫描件没有文字层或 OCR 失败。跳过；如果整本都这样，说明这本书没被正确索引。
3. **图注页 / 参考文献页**：命中的是引用或图注，不是正文。换词。
4. **书名页 / 版权页**：命中书名不代表内容相关。跳过。

两轮都查不到时：

- 先把词减到 2–3 个最核心的词再试一次；
- 再换同义位或英文术语试一次；
- 三步都没有，才回答"库里没有直接讲到这个的页"，并说明查过哪些词；不要编页码。

## 6. 引用格式

- 每条实质性结论后面跟 `<path> p.<page>`；多页写 `<path> p.<page>, p.<page>`。
- 只引用真正读过的页：命中片段没展开、没读上下文，就不要给它页码。
- 直接引用原文时不超过两句，用引号标出；转述不加引号。
- 同一个结论有多页支持时，引最直接的一页，其余在括号里补页码即可。

## 7. 工具速查

| 工具 | 用途 |
| --- | --- |
| `kb_query` | 主入口：`query`、`topK`、`expand`、可选多写法；一次一个词袋 |
| `kb_inventory` | 确认书库索引了哪些文件、有没有漏掉整本书 |
| `kb_lint` / `kb_suggest_links` | 维护笔记用，不用于回答问题 |

## 8. 收尾检查

- [ ] 拆出来的是 3–8 个词，不是一个整句。
- [ ] 中文和英文各查过至少一轮（术语有标准英文名时）。
- [ ] 命中按 `path + page` 合并过，相邻页没有重复计数。
- [ ] 前 1–2 条展开读过，知道它在回答什么。
- [ ] 每条结论都有 `<path> p.<page>`，没有编造页码。

## 9. 反例

- ❌ 把用户整句话丢进 `query`：命中全是高频词所在的页。
- ❌ 中英混在一个 query 里：两种语言都排不到前面。
- ❌ 只看第一条命中就下结论：第一条常常是目录页或书名页。
- ❌ 展开十页再慢慢挑：上下文被占满，真正相关的那页反而没读。
- ❌ 查不到就说"书上说"：没有页码就不是书里的结论。
